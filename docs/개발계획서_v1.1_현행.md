## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 목적 | 유튜브 자동자막이 제공되지 않는 영상(중국어 발화, 방언 포함) 대상, 한국어 번역 자막을 오버레이 제공 |
| 1차 타겟 콘텐츠 | 웨이보(微博) 라이브를 녹화하여 유튜브에 업로드한 영상 (VOD) |
| 타겟 페르소나 | 20~30대, 중국어 미숙, 중국 배우/아이돌 콘텐츠 소비층 |
| 로드맵 우선순위 | 1단계(유튜브 VOD) 확정. 2단계(웨이보 등 원 플랫폼 오버레이)는 별도 로드맵 |
| 출력 형태 | 한국어 번역만 오버레이(중국어 표기 비필수, 내부 파이프라인상 생성됨) |
| 차별화 포인트 | **[v1.1 수정]** "시청 흐름을 끊지 않는 오버레이 자막" — 실시간/준실시간 여부는 §3-0 오디오 확보 방식 결정에 종속. tabCapture 채택 시 실시간, 서버 배치 채택 시 준실시간(사전 처리 후 재생 동기화)으로 포지셔닝 확정 |

## 2. 요구사항 확정 사항 (v1.0과 동일)

1. 비용: 최대한 저렴 — 오픈소스 모델 + 무료/저비용 API 조합 우선
2. 언어: 중국어(표준중국어 + 방언), 발화자는 중국인 기준
3. 번역 방향: 중국어 → 한국어
4. 고유명사 용어집: MVP 우선 개발 후 추가 구축 (1단계 범위 제외)
5. 저작권: 오버레이 도구는 원본 재배포 없음. 원본 콘텐츠 리스크는 별도 인지, 법률자문 필요

## 3. 기술 검토 결과

### 3-0. [v1.1 신설] 오디오 확보 방식 — P0 최우선 결정 항목

카운슬 판정: 계획서 v1.0 최대 공백. 아키텍처·ToS 리스크·비용·포지셔닝이 전부 이 결정에 종속됨.

| 방식 | (a) 탭 오디오 실시간 캡처 (chrome.tabCapture) | (b) 서버 다운로드 후 배치 처리 |
|---|---|---|
| 동작 | 사용자가 영상 재생 중 브라우저 탭의 오디오만 캡처하여 처리 | 영상 URL을 서버로 전송, 서버가 오디오 추출 후 전체 처리 |
| ToS 리스크 | 낮음 — 콘텐츠 다운로드·복제 없음, 재생 중 소리만 처리 | 있음 — 유튜브 스트림 무단 다운로드 금지 조항 저촉 소지 (확인필요: 법률자문 대상) |
| 자막 품질 | 스트리밍 STT라 문맥 창이 짧아 정확도 다소 하락 가능 | 전체 오디오 일괄 처리로 정확도 유리 |
| 지연 | 발화 후 수 초 내 표시(실시간) | 사전 처리 필요(영상 길이에 비례, 재생 전 대기 발생) |
| 비용 구조 | 사용자 기기(온디바이스) 또는 소규모 스트리밍 서버 | 서버 GPU 상시/온디맨드 필요, 사용자 증가 시 비용 비례 증가 |
| "실시간 오버레이" 포지셔닝 정합성 | 부합 | 불부합(준실시간으로 문구 수정 필요) |

**결정 방침**: P0 파일럿에서 (a)(b) 모두 프로토타입하여 품질·지연 실측 후 확정. 사전 우선순위는 (a) — ToS 리스크·비용·포지셔닝 3개 축에서 모두 유리하나, 스트리밍 STT 품질이 시청 가능 수준인지가 관건.

### 3-1. STT (음성인식)
| 모델 | 채택 사유 |
|---|---|
| Qwen3-ASR (1차) | 52개 언어·방언(중국어 방언 22개 포함), 경량 0.6B~1.7B |
| SenseVoice (대안) | 광둥어 포함 50+ 언어, Whisper 대비 벤치마크 상회, 고속 |

**[v1.1 추가]** 방언 요구사항 실측 검증: 타겟 콘텐츠(배우·아이돌 방송)의 실제 발화가 표준중국어 위주일 가능성 있음(카운슬 아웃사이더 지적, 추측입니다). 파일럿에서 실제 샘플의 방언 비중을 측정하여 요구사항 수준 재조정.

### 3-2. MT (번역)
| 서비스 | 역할 |
|---|---|
| DeepL Free (1차) | 월 50만자 무료 |
| Papago (대안) | 아시아 언어 특화, 무료한도 확인필요 |

**[v1.1 추가] 무료한도의 성격 재정의**: DeepL 50만자는 개인용 규모임. 사용자 수십 명 이상 확대 시 즉시 소진(카운슬 반론가 지적). 대응: ① MVP는 클로즈드 베타(소수 사용자)로 한정 ② §3-4 캐싱으로 소모량 절감 ③ 확대 시점의 유료 전환 임계점을 §5 비용 모델에서 사전 정의.

### 3-3. 인프라
- 방식 (a) 채택 시: 온디바이스 우선 검토(경량 모델이므로 가능성 있음, 파일럿 실측 필요), 불가 시 소규모 스트리밍 서버
- 방식 (b) 채택 시: GPU 온디맨드(RTX 4090급 시간당 약 $0.40, A100급 약 $0.72)

### 3-4. [v1.1 신설] 자막 캐싱 전략 (비용 절감 핵심)

카운슬 피어리뷰에서 전원 누락으로 지적된 항목.

- 동일 영상(video ID 기준)에 대해 이미 생성된 자막은 재처리하지 않고 캐시에서 제공
- 팬덤 특성상 동일 영상을 다수 사용자가 반복 시청 → STT·MT 비용이 "영상 수"에만 비례하고 "시청 수"에는 비례하지 않게 됨
- 효과: MT 무료한도 소진 속도 및 GPU 비용을 구조적으로 절감
- 구현: video ID → 자막 데이터(타임스탬프+한국어 텍스트) key-value 저장소
- 유의: 캐시 서버 운영 비용(소액) 발생, 방식 (a) 채택 시에도 캐시 우선 조회 → 미스 시에만 실시간 처리 구조 가능

### 3-5. 저작권 (v1.0 검토 유지 + 순서 조정)
- 오버레이 플러그인 자체: 선례 존재, 재배포 없는 구조로 낮은 리스크
- 원본 콘텐츠(웨이보 재업로드): 원칙 친고죄이나 영리목적/상습성 인정 시 비친고죄 전환 — 업로더 리스크, 개발사 직접 책임 아님
- **[v1.1 순서 변경]** OSP 면책·유튜브코리아 정책 법률자문: 기술 파일럿 통과 후 진행(카운슬 실행가 판정 — 품질 미달 시 자문 비용 자체가 매몰비용)
- **[v1.1 추가]** 방식 (b) 채택 시 유튜브 ToS(다운로드 금지 조항) 저촉 여부를 법률자문 범위에 추가

## 5. [v1.1 신설] 비용 모델 — 부담 주체와 지속가능성

카운슬 판정 반영: "저비용"은 목표이지 모델이 아님.

| 단계 | 운영 형태 | 비용 부담 | 월 비용 상한(목표) |
|---|---|---|---|
| MVP (클로즈드 베타) | 소수 사용자(수~수십 명) 한정 배포 | 개발자 부담 | GPU 온디맨드 + 캐시 서버 소액 — 구체 상한은 파일럿 후 산정 (확인필요) |
| 확대 판단 시점 | DeepL 무료한도 70% 도달 또는 GPU 비용이 사전 상한 초과 시 | — | 임계점 도달 시 아래 중 택일 |
| 확대 옵션 | ① 사용자 후원/구독(팬덤 특성상 후원 수용성 있음 — 추측입니다) ② 사용량 제한(1인당 월 처리량 캡) ③ SRT 내보내기 등 프리미엄 기능 유료화 | 사용자 일부 부담 | 옵션별 시뮬레이션은 베타 데이터 확보 후 |

원칙: **사용자당 원가(영상 1시간 처리 원가)를 파일럿에서 실측하여 문서화**한다. 이 수치 없이는 어떤 확대 결정도 하지 않는다.
