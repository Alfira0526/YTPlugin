## 🔴 Q-1. 오디오 확보 방식 (a) tabCapture 실시간 vs (b) 서버 배치
- **왜 중요**: 아키텍처·ToS 리스크·비용·포지셔닝이 전부 종속(계획서 §3-0). 인수인계서상 **미확정 시 P1(설계) 진입 금지** 항목.
- **현재 처리**: 오버레이 렌더링 레이어는 (a)/(b) 공유이므로 먼저 개발 중. 자막 공급원을 인터페이스로 추상화하여 **어느 쪽이든 나중에 꽂을 수 있게** 함 → 개발은 계속됨.
- **사전 권고(계획서)**: (a) tabCapture 우선 — ToS·비용·포지셔닝 3축 유리. 단 스트리밍 STT 품질이 관건.
- **요청**: (a)/(b) 중 어느 방향을 1차로 갈지. (미정이면 계속 (a) 가정으로 설계 준비만 진행)

## 🟡 Q-2. 번역 품질 개선 우선순위 — 고유명사 용어집 조기 도입 여부
- **배경**: 파일럿 ②에서 고유명사 오류(미란→밀라노, 커모호→코모 호수, AD)가 주요 약점으로 드러남. 계획서는 용어집을 "MVP 이후"로 뒀으나, 실측상 체감 품질에 큰 영향.
- **현재 처리(자료구조만 마련, 기본 off)**: `pilot/glossary/`에 용어집 로더·적용(`Glossary`)과 시드(`seed.json`)를 구현. 파일럿 파이프라인에 **opt-in**(`--glossary`)으로 통합, 기본은 비활성. 시드로 파일럿 ② 오류 5개(미란/커모호/모커호/AD라디오/디자인위원회) **교정 확인**.
- **요청**: 용어집을 **MVP 기본 활성**으로 앞당길지(품질↑), 계획대로 이후로 둘지. (미정이면 계속 opt-in 유지하며 시드만 점진 확장)

## 🟡 Q-3. MVP 자막 공급 방식(초기) — 실시간 처리 전 '사전 생성 SRT 로드'로 시작?
