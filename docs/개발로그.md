## 세션 2026-07-19 (야간) — 오버레이 렌더링 레이어 개발 착수

### 협의: 무엇을 개발할 것인가
- 🟢 기획자: 파일럿으로 기술 실현성·"쓸 만한 품질" 확인됨. 제품 핵심 차별점인 **오버레이**(계획서 §1)를 만들자. 사용자 체감 가치가 여기 있음.
- 🔴 개발자: 인수인계서상 **오디오 방식 (a)/(b) 미확정 시 P1 진입 금지**. 아키텍처를 못 정박음. 단 **오버레이 렌더링은 (a)/(b) 공유**. 자막(타임스탬프+한국어)을 받아 영상 위에 그리는 부분은 오디오 방식과 무관 → **자막 공급원을 인터페이스로 추상화**하면 게이트 위반 없이 진행 가능.
- ⚪ 보안담당자: 동의. 오버레이 레이어는 **민감 권한 불요**(오디오 권한은 (a) 결정 후). MV3 + 최소 권한(youtube.com, storage)만으로 가능 → 웹스토어 심사 리스크(§6) 낮음. 지금 만들기 가장 안전한 조각.

### 합의된 결정
1. (a)/(b)와 **무관하게 공유되는 오버레이 렌더링 레이어**를 Chrome 확장(MV3)으로 개발.
2. **자막 공급원(SubtitleProvider)을 인터페이스로 추상화** — 지금은 정적/파일 SRT 로드, 실시간 (a)/(b)는 나중에 구현.
3. **최소 권한 원칙**: manifest에 tabCapture 등 민감 권한 미포함. host_permissions는 youtube.com로 한정, storage만 사용.
4. UX는 계획서 §4 반영: 자막 **위치·크기·배경 투명도 사용자 조정**, on/off.
5. 코어 로직(파싱·싱크)은 **순수 함수로 분리해 테스트 가능**하게, Chrome API 의존은 얇은 어댑터로.

### 아키텍처 (오디오 방식 중립)
```
[자막 공급원]                [자막 트랙]        [오버레이]
SubtitleProvider  ──cues──▶  SubtitleTrack ──▶ Overlay(DOM)
  ├ StaticProvider (지금: video_id→SRT, 캐시 정합)      ▲
  ├ (미래) RealtimeProvider-a (tabCapture 스트리밍)     │ video.currentTime 싱크
  └ (미래) BatchProvider-b (서버 사전처리)          [YouTube <video>]
```
- 이 구조에서 (a)/(b) 결정은 "어떤 Provider를 쓰느냐"로 축소됨 → 게이트 결정을 미뤄도 오버레이·트랙·싱크·설정 UI는 완성 가능.

### 결정 큐 등록
- Q-1 (a)/(b) 오디오 방식, Q-2 용어집 조기 도입, Q-3 사전생성 SRT 우선 → `결정대기_큐.md`.

### 산출 (이 세션) — 완료 ✅
1. **`extension/` MV3 확장 (오버레이 레이어)**: 자막 코어(SRT 파싱·트랙), 정적 공급원, 오버레이·콘텐츠 스크립트(싱크·SPA 대응), 팝업(설정·SRT 로드), 최소 권한 매니페스트, 데모 SRT.
2. **`pilot/cache.py` 자막 캐싱 (§3-4/D-8)**: video_id 기반 로컬 JSON, 파이프라인 통합(캐시 히트 시 STT·MT 생략), `--no-cache` 옵션.
3. **`pilot/glossary/` 고유명사 용어집 (Q-2, opt-in)**: 로더·적용(단일 정규식 패스)·시드, 파이프라인 opt-in(`--glossary`, 기본 off). 시드로 파일럿 ② 오류 5개 교정 확인.

### 테스트 결과 (전부 통과)
- 파일럿: smoke ok · 캐시 3건 · 용어집 5건 · compileall ok
- 확장: 코어 유닛 7건(node --test) · 실브라우저 DOM 통합 10 assertions(Playwright)

## 세션 2026-07-19 (b) — Q-1=(a) 결정 반영, 실시간 파이프라인 착수

- 🔴 개발자: tabCapture는 MV3에서 offscreen+사용자 제스처 필요. (a) 내부 서브결정(온디바이스 vs 서버, §3-3)은 Q-4로 분리. 실모델 전 STT/MT를 인터페이스+목으로 전체 흐름부터 검증. 실시간 STT 품질·지연이 최대 리스크(§3-0).
- ⚪ 보안담당자: tabCapture는 민감 권한 → 사용자 '시작' 시에만 캡처, offscreen 격리, 오디오 처리용만.

### 산출 (완료 ✅)
1. **실시간 코어(테스트 가능)**: `core/glossary.js`(JS 용어집), `realtime/stt-client.js`·`mt-client.js`(인터페이스+목), `realtime/realtime-provider.js`(캡처→STT→MT→용어집→onCue). 유닛 4건 통과.

## 세션 2026-07-19 (c) — 재생환경 검증 + (a) 실코드 진척

### 협의 요지
- 🔴 개발자: 실STT/실DeepL/실캡처는 실기기에서만 검증 가능 → 그 외 **검증 가능한 실코드**부터.
- ⚪ 보안: DeepL 키는 background만 접근(페이지 미노출), tabCapture는 사용자 트리거만.

### 산출 (완료 ✅, 모두 커밋·푸시)
1. **재생환경 호환성**: 공식 유튜브 PC 앱 없음 → PC "앱"=PWA(크로미엄) → 확장 커버. PWA는 팝업이 없어 **단축키(commands)로 시작**. 서드파티 네이티브는 범위 밖(Q-5). `docs/재생환경_호환성.md`.
2. **온디바이스 STT 스켈레톤**(Transformers.js/Whisper) — Q-4=온디바이스 확정, 인터페이스 뒤.
3. **DeepL 실번역**: 순수 헬퍼(`deepl.js`) + `DeepLMtClient`(background 위임, 키 미노출) + background fetch 핸들러. 팝업에 키 입력.
4. **실시간→캐시 연결**: 종료 시 cue→SRT 저장(`serializeCues`) → 재시청 즉시 표시(§3-4).
5. **실시간→오버레이 브라우저 DOM 통합 테스트** 추가.

### 테스트: 확장 유닛 16 + DOM 14(오버레이 10 + 실시간 4) 전부 통과. 전체 JS node --check·manifest 유효.
